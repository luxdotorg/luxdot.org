LuxDot v2.4.1 — Memory Atlas Fix
Date: 2026-08-10

FIXED
- Removed hard dependency on fetch(data/memory-atlas.json)
- Added embedded memory-data.js as primary offline/static-host data source
- JSON fetch retained only as fallback
- Replaced implicit DOM-ID globals with explicit getElementById references
- Memory tree now calculates radial positions dynamically and can grow beyond 7 nodes
- Map list items now open their corresponding memory nodes
- Added safer escaping and link attributes

CHECKS
- memory.js: Node syntax check PASS
- memory-data.js: Node syntax check PASS
- memory-atlas.json: JSON parse PASS
- local HTTP asset resolution: PASS (200 for memory.html, memory.css, memory.js, memory-data.js, data/memory-atlas.json, app.js, styles.css)
- Memory navigation links present across Home, Library, Projects, Qur'an, Tanakh, New Testament and research pages

ROOT CAUSE
The previous build loaded the Memory Atlas dataset exclusively with browser fetch(). This can fail under file:// previews, restrictive static-host configurations, MIME/CORS rules, or deployment setups that omit/redirect the JSON asset. The result is an empty Atlas even though memory.html itself opens.
